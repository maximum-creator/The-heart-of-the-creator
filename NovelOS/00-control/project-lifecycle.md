# 番茄小说项目经营生命周期

本文件管理“一本书是否值得继续投入”，不参与每章正文生成。只有总导演在立项、发布、签约反馈、数据异常或阶段复盘时读取，普通章节保持关闭。

## 状态

### 1. `CANDIDATE`：立项候选

- 产物：读者契约、差异化卖点、长篇发动机、事实风险、现金/积分试验预算。
- 退出门：核心体验能由前三章真实发生，不只靠简介和系统说明；否则淘汰或重做立意，不生成长总纲。

### 2. `CALIBRATING`：前三章校准

- 产物：同一模型低成本基线、三章小闭环、人工声线确认、实际积分与返修率。
- 退出门：硬错误清零，用户愿意继续读，成本没有越过新书试验预算。未通过时最多做一次有明确假设的局部修正，不无限洗稿。

### 3. `PILOT_PUBLISHED`：发布试水

- 动作：按平台当前要求创建作品、处理 AI 辅助声明/标识、稳定更新并记录时间。
- 观察：曝光、开读、章内/章间流失、追读、评论语义和更新稳定性。样本过小或推荐波动时保持观察，不把百分比极值当规律。

### 4. `SIGNING_REVIEW`：签约与平台反馈

- 先区分：资料/合规缺口、书名封面简介承诺、开篇兑现、正文留存、更新条件和平台外部因素。
- 自动评估或拒签原因只是线索；以平台正式通知、人工复核入口和当期规则为准。
- 补救动作只能命中一个主要假设：包装问题改包装，开篇承诺问题改前三章，正文留存问题定位跌点窗口；不默认整书重写。

### 5. `OPERATING`：签约后运营

- 稳定更新优先于频繁换模型和重构系统。
- 每个自然数据窗口只运行一个主要实验，保留前后样本、修改字数、模型积分和结论。
- 参与活动、全勤或流量扶持前核验当期资格与机会成本，不把活动奖励计入基础收入预测。

### 6. `RESCUE`：有限补救

只在存在可定位、可修改且有合理收益空间的问题时进入。允许的补救顺序：

1. 书名/封面/简介与正文承诺不一致；
2. 前三章没有兑现核心体验；
3. 明确章节跌点对应可复现的理解、节奏、人物或逻辑问题；
4. 更新节奏、分类或发布时间造成的外部干扰。

每轮只改一类变量，并预先写明观察窗口与停止条件。一次补救后证据仍不改善，不靠继续增加 Agent 或昂贵模型掩盖项目假设错误。

### 7. `STOPPED`：止损/归档

满足任一项时停止新增模型投入：

- 已达作者新书试验预算；
- 两次有隔离变量的补救均无可辨认改善；
- 核心卖点必须依赖人物降智、事实造假或平台不允许内容才能成立；
- 有效成稿成本长期高于可接受收入比例；
- 作者已不愿持续创作该题材，稳定更新不可实现。

停止不等于删除。保留正文、数据、有效人物机制、失败原因和可迁移经验；不得把失败书全文灌入新书，只迁移已验证的结构经验。

## 决策证据

每次状态迁移记录：日期、原状态、新状态、唯一主因、平台/文本/成本证据、做过的变量修改、尚未排除的外部因素和下个观察点。没有足够证据时保持原状态，不用乐观话术替代判断。
