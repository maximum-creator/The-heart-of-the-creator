# 新书前三章生产与发布门

版本：0.6.0

## 目的

前三章负责验证书名、简介和核心机制承诺是否能在真实人物行动中成立。它不是“每 300 字一个反转”的节拍模板，也不保证平台推荐；它只阻止尚未完成读者契约、人物因果和成本闭环的稿件进入真实发布。

## 零：立项信封

进入正文前只锁定六件事：

1. 目标读者及其已熟悉、仍愿意付出注意力的核心体验。
2. 书名和简介共同承诺的一句话体验，必须能由第一章场景兑现。
3. 主角的可见目标、能力边界、一个真实盲区和一个会长期付代价的选择倾向。
4. 至少两名关键人物各自最怕失去什么；不能都以帮助或反对主角为人生目标。
5. 前三章要完成的一次小闭环，以及它打开的长线问题。
6. 题材需要核验的事实类别；历史、职业、医疗、法律、军事和地域没有事实包不得凭印象写。

不先生成十万字总纲、百名角色卡或完整世界百科。能影响前三章选择的内容才进入 Packet。

## 一：三章功能，不锁写法

### 第一章：承诺落地

- 前 10% 让眼前目标、风险或关系张力进入场景。
- 核心卖点必须发生一次，不只由系统说明、回忆或未来预告。
- 主角得到不完整但真实的回报，并因自己的选择留下代价、暴露或新约束。
- 陌生名词只在当前选择需要时出现；读者无需先学会世界观才能知道人物想做什么。

### 第二章：后果不复位

- 第一章的代价必须改变资源、关系、敌方策略或信息可信度之一。
- 对手或配角根据自身利益调整，不重复上一章同一种反应循环。
- 主角优势再次有用时，必须遇到变化、盲区、误判或道德成本，不能连续无损通关。
- 至少一个旧细节被重新解释，而不是只增加新名词和更大敌人。

### 第三章：小闭环与长问题

- 完成一次“承诺—受阻—选择—后果”小闭环，使前三章本身有回报。
- 长线问题由已发生的选择推出，不能靠陌生电话、尸体、敲门或临时亲人遇险硬接。
- 关键配角至少有一次改变主角方案的独立选择；删除后，证据、选择或结果必须变化。
- 读者应能说出接下来想看的具体问题，而不是只知道“还有更强敌人”。

## 二：每章最小生产流

每章新开独立会话，禁止继承上一章的长对话历史。

1. 总导演生成 Context Manifest：把固定 Agent/Skill、读者契约短摘要、世界 HARD 和声线边界列为 stable；把最近一至两章必要状态差量、活跃人物、命中伏笔和本章事实列为 variable。
2. 使用 `NovelOS/tools/context/build-cache-context.mjs` 编译上下文；正文作者按 `stable-prefix.md`、`variable-suffix.md`、当次输出要求的固定顺序读取。stable 哈希未变化时复用原产物，禁止重述或改序。
3. 架构师生成最小 Chapter Packet，并在审计端生成最多3项状态转移契约：状态变化、前台问题、视角、人物损失、主动阻力、HARD、OPEN、NO-GO；专业事实契约标记为 NOT_REQUIRED、READY 或 BLOCKED。转移契约不进入正文作者输入。
4. READY 契约作为变量后缀加载；BLOCKED 先由研究编辑补最小事实包；NOT_REQUIRED 不携带空事实包。外部 claim 必须有 sourceIds，推导数字必须有 premiseIds 与 derivation。
5. 正文作者只生成一版初稿，不看完整审稿表和人工金标。
6. 确定性工具先扫字数、重复、标点、故事债、事实契约和命中硬轨迹；工具只定位，不自动洗稿。
7. 硬逻辑审计检查事实来源、能力、限知、时间、物资和因果闭合；工具命中率不能替代来源真实性判断。
8. 叙事编辑只选择一个最影响阅读动力的主问题和最多两个次问题，给出局部修改；不得整章二次创作。
9. 状态管理员只提取已批准变化，绑定最终稿哈希并引用正文原句，再运行状态转移核验。CALIBRATION 由用户确认整体声线；PILOT/PRODUCTION 可由完整自动验收回执批准，不要求用户逐章审稿。

普通章不得启动角色沙盘或多模型会审。只有重大关系冲突且删除测试失败，才让关键角色分别生成短行动意向，输出不得包含成品句子。

## 三：发布 HARD 门

任一项失败都不发布：

- 书名/简介承诺前三章没有真实发生。
- 关键事实、金额、时间、伤势、物品、能力或知识来源不闭合。
- 专业事实契约为 BLOCKED，或正文出现契约未授权的关键数值、阈值、维修/医疗/法律/工程步骤。
- 限知泄漏，或用作者全知替人物获得答案。
- 主角连续无代价获胜，配角只负责震惊、认可、送情报或被删除后剧情不变。
- 用新系统功能、新能力、临时仪器、突发救援、反派降智或假专业术语解决核心矛盾。
- 关键情绪没有触发与选择，只靠身体反应、旁白定性、宏大宣言或及时和解。
- 章末只有外加事故，没有当章回报和由既有因果产生的下一步。
- 文字墙、字幕式碎段、句号偏科或破折号密集已经损害手机阅读。
- 本章实际积分、返修次数或累计试验预算越过 `cost-budget.md` 的停止线。
- 要求发生的关键状态没有真实变化，或本应由人物选择造成的进展被系统、巧合、旁白代办；保护事实与活跃问题无法由定稿原文闭合。

## 四：人工体验门

硬门通过后，用户只判断五件事：

1. 我是否愿意继续读？具体想知道什么？
2. 哪个人最像活人，哪一处像模型在完成任务？
3. 有哪一段在解释已经看懂的东西？
4. 核心卖点是否真的发生，还是只听说以后会发生？
5. 这套声线是否愿意连续看十万字？

不要求用户给抽象总分。一个明确“不想读”的具体段落，比模型 9.5 分更有决策价值。

## 五：成本记录与晋升

每章记录 stablePrefixHash、稳定/变量字符数、冷暖状态、输入/输出 Token、缓存率、积分、耗时、有效成稿字数、人工改动字数和是否改变发布决策。前三章结束后计算每万有效字积分与返修率。不得为了提升缓存率额外调用模型；缓存率高但 HARD 失败仍按无效成稿计。

模型只有在同类未见任务连续三次通过 HARD、用户接受声线、成本未越界时才成为正式正文路由。昂贵模型若只让句子更华丽、没有减少硬失败或返修，不晋升。

## 六：真实数据反馈

发布后的曝光、阅读人数、章内流失和追读只用于形成假设：先排除样本过小、断更、推荐变化和上一章入口，再回看异常章节。一次 0%、50% 或 100% 不得晋升为规律；同一问题在新稿或多本书重复出现后，才更新系统规则。
