# 市场上架、文件交付与常见问题

## 两种交付方式

本仓库根目录是本地完整版，包含辅助程序、MCP 服务和工程模板。`marketplace/feelfish/` 是自包含市场版。两者的安装方式和复核能力不同，不能混用技能说明与文件依赖。

完整源码可以交给 FeelFish 客服评估，但客服是否支持代上架、完整工程附件及账号归属操作，须由平台确认。上传 `.mjs` 文件不等于平台会部署或运行它，上传 MCP 服务源码也不等于用户已完成工具配置。

## 为什么曾出现缺文件审核意见

旧技能引用了 `NovelOS/tools/eval/narrative-fingerprint.mjs` 等项目文件，但市场上传资源未携带相应文件，形成缺失依赖。`.mjs` 是 JavaScript 模块文件；问题在于交付依赖不闭合，不能概括为所有 `.mjs` 都违规。

官方[技能指南](https://www.feelfish.com/zh/docs/build-skills-for-novel)列有可选脚本目录，但具体市场审核和运行支持仍应向平台确认。市场适配版采用不依赖外部程序的文本复核，不能将其结果称为程序检查通过。

## 上传与更新

1. 导入前确认当前项目路径和资源来源；保留已有作品与自定义配置。
2. 检查方案主智能体、11 个智能体及16 项技能绑定。源码静态检查可运行 `node scripts/check-marketplace.mjs`。
3. 上传时分别核对技能、智能体、方案的状态。“市场中已存在，已引用”不证明新内容覆盖了旧资源。
4. 应用提示：更新方案不会自动更新其引用的智能体和技能；已有资源应分别使用更新流程。
5. 审核通过以平台状态为准，不以本地检查、上传请求发出或文件存在为准。

## 409 与 EPERM 不是同一个问题

- **409 / Website request was rejected**：服务端拒绝请求。2026-09-06，项目维护者转述客服反馈：24 小时内上传超过 100 个文件可能触发上传限制，表现为 409。这是本次客服反馈，不是已核验的公开限额规范；计数口径、恢复时间与后续政策应由平台确认。不能仅凭 409 判定 ID 冲突，也不应通过换账号或资源 ID 绕过限制。
- **EPERM / rename**：本机导入时无法替换文件，与服务端上传限额不同。可能涉及占用、权限或应用替换逻辑；不要连续重复导入、删文件或全盘修改权限。先保存工作并核对来源、目标路径及已有内容。
- **没有本地方案**：确认当前书的 `.feelfish/solutions/` 与配置是否实际存在，尤其注意新建项目产生的下一层书名目录。

## 交给客服时怎么说

> 这是开源 NovelOS 创作系统。请评估完整工程分发，或代为上架 `marketplace/feelfish/` 中的市场资源，并归属到当前客服工单认证的用户账号。原方案 ID 为 `novelos-creator-heart`，请先核查既有记录与归属，再决定更新或创建。请分别核对技能、智能体、方案的新版本和审核状态。若平台不支持运行脚本或 MCP，请明确提供市场适配版及完整版下载入口，不宣称市场导入自动具备全部程序能力。

不要提供密码、API Key、登录令牌或验证码。分享包应来自干净的开源源码，排除用户小说、运行记忆、账号关联记录、Git 历史和新书子项目。客服代上架和账号归属尚需实际确认，不是本仓库已经实现的功能。
