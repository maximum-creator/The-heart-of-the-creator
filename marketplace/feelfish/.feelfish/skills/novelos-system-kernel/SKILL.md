# 市场版创作调度
按任务组建最小团队，不固定串联全部角色。本技能独立提供调度协议。
## 模式
FAST：普通章，单章包、单初稿、针对已有事实的简要复核；没有风险不追加昂贵审稿。
STANDARD：重要人物关系、复杂状态或明确阅读损失；加入对应专业角色，一次合并审查。
DEEP：立项、卷级转折、高潮或高风险考据；先发散机制不同的短方案，再研究、收敛，不并行生成整章。
## 任务信封
每次交接给出目标、负责人、最小输入、允许写入范围、禁止改变的事实、预算或最多调用次数、完成条件。资料已保存且接收方有读取工具时传用户确认的路径；接收方无读取工具时必须把必要内容直接放进输入，不能只给路径。
调用子智能体前确认该角色和宿主调用工具存在。不存在时交付待执行任务和缺口，不伪称已经委派。不需要组队的小任务直接处理。
正文作者不带工具，仅接收闭合的单章输入；每章新会话，默认一版初稿。专业讨论只在同一未完成任务、上下文仍干净时延续会话。
## 共享状态与边界
HARD 为已批准事实，冲突必须停止；SOFT 为可以调整的审美与规划；OPEN 是作者自由空间。发散阶段不加载细碎审稿禁忌。
每阶段只记录任务状态、候选产物、剩余缺口和下一负责人。没有项目资料时先在本轮形成最小读者约定与状态摘要，不要求用户寻找预装模板。
市场版不提供程序验收或自动提交机制。语义复核不能称为机器审计通过。未解决的硬冲突不定稿；用户批准后才由状态管理员更新正式记录。对外发布需用户另行授权。
## 完成
交付候选稿或明确缺口、主要创作决策和未解决风险。无真实计费数据时不捏造 Token、缓存率、费用或收益。不会改变决定的额外调用停止。

## 市场版输入与能力边界
本技能可直接处理用户提供的相关文本。本文所称章节包、读者约定、事实包或状态记录是本轮输入/产物，不是需要另行下载的预装文件。缺关键事实时只请求最小补充；已有资料不重复索取。只能使用宿主实际提供的工具，无法读取/保存时返回文本与缺口，不声称执行或保存成功。
