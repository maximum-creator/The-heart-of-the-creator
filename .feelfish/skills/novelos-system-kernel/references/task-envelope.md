# 子智能体任务信封

每次委派使用以下任务内容，未涉及的字段可省略。这些字段放入任务说明，不是新增的 `call_sub_agent` API 参数。

```yaml
task_id: 本轮唯一编号
mode: FAST | STANDARD | DEEP
goal: 要解决的创作问题
owner: 本次唯一负责的 Agent
required_skills: [] # 仅列本次确实需要的准确技能标识；职责本身足够时允许为空
allowed_tools: [] # 明确本次必要工具；与宿主实际权限取交集，不用此字段冒充权限已生效
read:
  - 只列项目相对路径
write:
  - 本 Agent 唯一允许修改的产物
hard_constraints:
  - 已批准事实或不可违反项
open_space:
  - 允许自由探索的问题
budget: S | M | L
deliverable: 期望的产物或差量格式
persist_by: 有写权限的保存负责人；只读 Agent 返回差量，由该负责人保存候选
acceptance: 能判断完成的条件
do_not_touch:
  - 不属于本 Agent 的文件或决策
```

预算含义：`S` 只读摘要和当前场景；`M` 可读相关状态与最近章节；`L` 仅用于立项、卷级设计和高风险研究。输出应短于输入材料，除非任务就是写正文。

## 派发、回执与交接

- 派发前确认职责、技能存在性、输入范围与读写权限。复用已有产物前核对输入版本和适用范围；有可靠版本或哈希就引用，没有则回读相关输入确认，不能编造哈希。不得为证明“技能用过”重复已完成工作。
- `required_skills` 表示必须实际加载并应用，不是只在回复里报出名字。仅指定与本次问题匹配的技能；可选能力只有出现具体缺口才补充，不默认加载全部绑定技能。
- 缺技能、缺输入或缺权限时返回 `blocked` 和具体缺口，不静默换用无关技能。该状态仅指子任务，不改变用户目标状态。
- 回执只需：`status: success|warning|blocked`、`summary`、`artifacts`（路径或返回差量）、`skills_used`、`unresolved`。`skills_used` 的宿主加载记录优先；只有模型自述时标记 `self_reported`，不可宣称已经获得独立执行证据。
- 总导演验收的是产物能否解决原任务。人物设计必须有情境中的动机、行动及后果，只有性格标签不算完成；不能用自评分替代正文或人物证据。
- 只读角色不写文件。`persist_by` 保存候选并回读确认后才能向下游交接路径；保存失败不得报成功。未批准产物不进入正式 Canon。
- 失败只做一次针对缺口的修复；仍不满足则返回明确问题，不循环调用或暗中重写整章。
