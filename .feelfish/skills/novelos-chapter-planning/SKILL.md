# 章节规划与上下文编译

## 第一步：只取必要上下文

优先读取：当前卷、最近 2 至 3 章、出场人物当前状态、相关事件、活跃伏笔与承诺、世界硬规则、活跃错题。不得因模型窗口很长而读取整本书。

生成 Context Manifest，列出：

- 必须读取的文件或片段及用途。
- 可选检索项。
- 明确排除的无关资料。
- 未解决冲突和可信度。

## 第二步：生成最小 Chapter Packet

正文作者只接收能产生本章的核心包：

1. 本章要改变什么，以及读者当前最想知道的一个问题；开篇前 10%（短章约前 300 字）应能由场景自然显出眼前目标、风险或关系张力，不另写说明段。
2. 视角、时间、地点和不可改的开场状态。
3. 出场人物此刻各自想得到什么、准备采用什么策略、最怕失去什么；重要人物必须有可与主角方案冲突的“损失函数”，不能只填性格标签。
   多人对话章只摘取出场人物的注意力偏向、知识/词汇边界、关系姿态与压力策略，不传完整人物卡或预写对白。
4. 能主动变化的阻力，以及它为什么不是等待主角击败的靶子。
5. 本章必须形成的一项可观察状态变化；锁定结果边界，不预写达到它的步骤。正文中的行动顺序、受阻方式和局部解法保持动态。
6. `HARD`：只列违反后会造成逻辑或承诺崩塌的事实。
7. `OPEN`：至少保留行动顺序、即时反应、场景细节或局部结果中的三项由正文作者决定。
8. `NO-GO`：只列本章最可能发生且代价最大的越界。

同时生成一份不超过 3 项的 `chapter-transition-contract`。它不是节拍表，只锁定本章必须跨过的状态边界：进入时是什么、离开时至少改变到什么方向、该变化是否必须由人物选择造成，以及哪些既有事实/未解决问题不得被静默改写或提前抹平。若必须变化超过 3 项，说明本章负载过重，先合并主因或拆章；不能把所有动作写成 transition。

若本章触发历史、职业、医疗、法律、机械、工程、军事、金融、药物、精确载荷或关键操作步骤，必须同时生成 `professional-fact-contract`：

- `packet` / `canon` 事实指向项目内来源；`external` 事实必须指向已核准事实卡；`derived` 数值必须列 premiseIds 和计算过程。
- Packet 没提供的体重、剂量、承重折减、维修参数、操作步骤和专业阈值不得靠“常识”补齐。
- 资料齐全标记 READY；缺关键事实标记 BLOCKED 并先交研究编辑；普通生活章标记 NOT_REQUIRED，不加载事实包。
- 契约只授权可写结论，不预写正文句子，也不限制无事实风险的动作、表情、环境和人物选择。

若物理环境、专业条件或证据物会真正限制选择，只记录一个会参与因果的材料约束，例如重量、伤势、潮位或唯一物证；不得把“雨声、冷风、灯光”等装饰性细节预制成正文句子。

伏笔、人物知识、情绪余波、物品、能力、伤势、金钱、专业事实、重复风险和系统面板不是固定栏目。只有本章确实触发时才附一小段相关条目，不加载整本账本。事实契约为 READY 时，只把本章契约文件作为变量后缀加入 Context Manifest；NOT_REQUIRED 时只保留 Packet 中的一行状态，不附空事实包。

## 规划与写作隔离

- 架构师可在内部检查承诺、伏笔、资源、人物弧和重复风险，但不得把完整审稿清单转交正文作者。
- 若 Chapter Packet 已规定每个节拍、成品情绪、笑点、比喻、段长或章末句，判为过度规划，退回压缩。
- 若 `HARD` 超过正文作者可同时记住的范围，先合并为更高层因果或移回审计端；不能用增加提示词解决规划混乱。
- 只指定关键选择的压力与后果，不指定“角色必须选择A”。人物在现场作出更合理选择时允许偏离，并由审计判断是否需要更新规划。
- 资源账本、事实包和伏笔细节由审计员按需读取；正文作者只看到影响眼前选择的结果。

章节包是生成边界，不是逐句剧本。模板见 `assets/context-manifest-template.md` 与 `assets/chapter-packet-template.md`。

交给正文作者前做一次双向检查：如果另一个写作者无法仅凭 Packet 还原本章必要的行动因果、关系变化与出口状态，说明缺少关键接口；如果他几乎只能写出唯一动作顺序、对白和情绪落点，说明规划过密。前者只补不可替代的接口，后者删回功能、压力、边界和状态变化，不靠增加篇幅折中。契约模板见 `NovelOS/05-chapter/chapter-transition-contract.template.json`；它留在审计端，不进入正文作者输入，避免正文逐条表演状态字段。
