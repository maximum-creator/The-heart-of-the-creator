# Token 与模型经济

优化目标是单位积分获得的可发表质量，不是单纯减少调用。

1. 先用 NovelOS MCP 估算上下文和候选模型积分，再决定 FAST、STANDARD 或 DEEP。
2. 静态规则放在 Skill；动态背景放项目文件；委派时只传路径和差量。
3. 主调度、状态提取、重复扫描使用低价模型或确定性工具；创意合成、复杂情感和高风险考据才使用强模型。
4. 同一 Agent 只有在同一未完成任务且历史仍干净时使用 `continueSessionId`；章节正文一章一会话，禁止用长历史换取表面缓存率。
5. 每次昂贵调用前写出要验证的假设；结果没有改变决策则降低下次路由权重。
6. 重试只用于网络、限流和服务异常；结构错误先缩小任务，不盲目重复生成。
7. 本轮调用写入 `NovelOS/08-analytics/model-cost-log.md`，记录模型、角色、输入/输出 Token、积分估算、是否改变决策和产物评分。
8. 读取 `NovelOS/00-control/cost-budget.md`；缺少收入、积分折算或预算数据时返回 UNKNOWN，只按积分上限控制，不伪造人民币成本。
9. 成本估算使用当前时段倍率；DeepSeek 非紧急批量任务可避开工作日北京时间高峰，但不能为省积分错过更新窗口。
10. 前三章允许较高验证投入；稳定后昂贵叙事模型默认每 5 章抽检 1 章，只有重大转折、数据异常、E1—E17 命中或用户不满意才恢复逐章调用。
11. 同一任务首次失败先判断是上下文、规则还是模型问题；没有新假设不得花钱重复抽卡。连续两次昂贵调用未改变决策，自动降级为低价模型或确定性检查。
12. 路由比较使用真实总 Token，包括隐藏思考、缓存未命中和重试。单 Token 便宜但为同一结果消耗数倍思考 Token 的模型，不得标记为“省钱”。
13. 正文模型按“通过硬门后的单位积分质量”排序；逻辑审计、标点段落统计和重复扫描优先用确定性工具，禁止用昂贵模型完成可计算工作。
14. 新会话第一次正文调用、切换方案或切换 Agent 后，先运行 `node NovelOS/tools/config/check-agent-overrides.mjs --root .`。返回 `BLOCK_MODEL_CALL` 时不得发送；`PASS` 只证明运行时覆盖与方案一致，不代表费率或预算已经通过。
14. 读取 `NovelOS/00-control/cache-policy.md`。正文上下文先用本地脚本编译为字节稳定的固定前缀和本章变量后缀；不在提示词中加入时间戳、绝对路径、运行 ID 或随机措辞。
15. 不发送专门的付费预热请求。第一次冷请求只记基线；相同前缀的自然后续请求低于 60% 才诊断，暖请求 70% 是成本预警目标而非质量门。
16. 同时记录 `stablePrefixHash`、稳定/变量字符数、冷暖状态、总 Token、缓存率、实际积分和有效成稿字数；最终以通过发布门后的每万有效字积分判断效率。

初始模型只是先验，按 `NovelOS/06-learning/model-scorecard.md` 的盲测结果更新，不把一次好稿永久绑定成“最佳模型”。
