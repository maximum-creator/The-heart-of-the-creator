# 长篇章节生产子流程

本 Skill 只描述 STANDARD 章节生产，不是整个 NovelOS 系统。主智能体先用 `novelos-system-kernel` 判断是否应走 FAST、STANDARD 或 DEEP；不要对所有任务强制执行下列步骤。

## 核心门禁

1. STANDARD 默认顺序为：准备资料/必要考据 → 事件因果与人物情感协作 → 章节包 → 初稿 → 风险触发的审计 → 一次局部修订 → 用户终审 → 状态提交。
2. 硬事实缺失、相互冲突或来源不成立时停止，输出最小缺口，不自行圆设定。
3. 草稿、审稿意见和候选事实都不是正式 Canon。
4. 只有用户明确说“批准定稿”，状态管理员才可写入正式状态。
5. 正确段落冻结；局部问题不得触发整章重写。
6. 默认只生成一版初稿和一次合并修订；第二次修订只处理残留 P0、明确回归错误或用户指定问题。
7. 只有明确需要时才委派工具管理员运行低成本的结构、重复、状态或事实完整性工具；强模型只用于关键决策、复杂人物冲突、史实高风险或已有证据命中质量风险的段落。
8. 不允许多个隐藏编辑依次重写同一段正文；每次模型调用必须有唯一职责和可检查产物。

## 主智能体步骤

1. 读取 `NovelOS/00-control/workflow-state.md` 与当前项目清单。
2. 把大纲与状态整理任务交给故事架构师，必要时先由研究编辑生成事实包；取得 Context Manifest 和 Chapter Packet，并通过跨章重复预检。
3. 把确认后的章节包交给正文作者，只生成一版初稿。
4. 把初稿交给硬逻辑审计员。存在 P0 时禁止进入润色。
5. P0 清零后，只有在前三章、重大转折、新视角、抽检章、读者数据异常、E1—E17 命中或用户不满意时，才交给昂贵叙事编辑依据本书 `reader-contract.md` 做一次合并检查；普通稳定章由总导演运行低价门禁，命中风险再升级。修订单只保留一个主问题和最多两个次问题。
6. 需要修改时，只生成明确的局部修订单并复查受影响段落。
7. 按 `NovelOS/09-evals/market-text-quality-gate.md` 输出发布、最小修订后发布或退回重构，并向用户提交候选稿与未解决风险；等待批准。
8. 批准后交给状态与学习管理员提交状态差量，并关闭本章。

详细状态定义按需读取 `references/workflow-states.md`。
